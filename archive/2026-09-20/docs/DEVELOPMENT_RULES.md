# VelaOps Sentinel 工程与提交规约

> 团队与 AI Agent 后续开发的默认执行规则。
> 最后更新：2026-08-24

## 1. 基线保护

1. 开始任务前检查队伍仓以及涉及的 openvela 子仓 `git status` 和 `git diff`。
2. 现有本地修改默认属于用户，不覆盖、不回退、不夹带到无关提交。
3. 未经用户明确同意，不用远端分支覆盖本地重构基线，不执行 pull、merge、rebase 或 reset。
4. 作品代码优先放在队伍仓，通过 manifest `linkfile` 映射；公共仓改动单独记录上游依赖和后续 PR 方向。

## 2. 任务粒度

每个任务必须是一个可独立验收的功能切片，开发前写清：

- 用户或系统行为；
- 输入、输出和错误语义；
- 所属层次和依赖边界；
- 安全约束和失败降级；
- 可自动化验收条件；
- 是否需要编译、烧录或真机测试。

同一任务不混入无关重构、新功能、全局格式化和不相关 Bug 修复。

## 3. 分层与解耦

```text
Presentation  LCD / LED / CLI
      ↓
Application   用例编排
      ↓
Domain        状态机与领域模型
      ↓
Ports         传输、存储、时钟、Agent、硬件接口
      ↑
Adapters      HTTP/HMAC、SD、ai_agent、NuttX 驱动
```

- Domain 不包含 LCD、HTTP、SSH、JSON 库或 NuttX 设备节点细节。
- UI 不直接调用网络和运维 Action。
- 网络适配层不决定业务风险和授权策略。
- 存储格式与领域模型通过版本化 DTO 隔离。
- 跨层通信使用小而稳定的接口，避免全局可变状态。
- 模块内部保持高内聚；公开头文件只暴露调用方真正需要的类型和函数。

## 4. 编码约定

- 新增业务代码使用中文注释。
- 注释重点解释设计原因、安全边界、并发假设、硬件限制和非直观算法。
- 不为自解释的赋值、分支或函数调用添加无效注释。
- 对外 API 明确所有权、线程安全、超时、错误码和长度上限。
- 日志不输出密钥、密码、Token、完整请求头或未脱敏服务器输出。
- 每个外部输入都做类型、长度、范围和枚举校验。
- 嵌入式路径明确堆、栈、缓冲和重试上限，禁止无界增长。

## 5. 测试门禁

### 5.1 纯逻辑与协议

- 主机端单元测试；
- 正常、边界、非法输入、超时和重试用例；
- 固定协议测试向量，特别是 HMAC 签名与 JSON schema；
- 密钥和敏感字段的日志脱敏测试。

### 5.2 设备端代码

- 格式和静态检查；
- 对应 board config 的增量编译；
- 仅在 defconfig/Kconfig 改动、依赖失配或增量产物可疑时做干净编译；
- 硬件、网络、持久化、时序或内存相关功能必须真机验证。

### 5.3 Proxy 与端到端

- Proxy 单元和集成测试；
- 错误签名、过期时间戳、nonce 重放、schema 越界和 Action 越权测试；
- 模拟超时、断线、半成功执行、超大输出和非法 UTF-8；
- 在受控测试服务器完成一次完整闭环。

## 6. 编译、烧录与串口

- 编译从工作区根目录调用：

  ```bash
  ./build.sh vendor/espressif/boards/esp32s3/esp32s3-eye/configs/openvela
  ```

- 只改应用源码时优先增量编译，不无意义地 distclean 和重拉 HAL。
- 烧录前用 `ls /dev/ttyACM*` 确认目标，不假定端口固定为 `/dev/ttyACM0`。
- 烧录使用 `esptool.py`；交互使用 `docs/tools/` 的 raw tty 脚本，不切换 DTR/RTS。
- 真机测试记录固件哈希、大小、测试命令、关键输出和结论。

## 7. 一功能一提交

每个功能按以下顺序收尾：

1. 执行该功能所需的全部测试。
2. 查看 `git status --short` 和 `git diff --check`。
3. 逐文件检查 diff，排除无关改动、临时调试代码和敏感信息。
4. 只 stage 当前功能文件。
5. 使用语义清晰的中文 commit，例如：

   ```text
   文档：统一 Plan C 架构与开发规约
   功能：实现 Proxy HMAC 请求校验
   测试：增加 HMAC 协议测试向量
   修复：改用单调时钟计算 LLM 超时
   ```

6. 提交后检查 `git show --stat --oneline HEAD` 和工作树，确认提交边界正确。

测试未通过时不得使用“完成”类提交信息。临时/WIP 提交不得进入正式交付历史。

## 8. 减少重复消耗

- 优先用主机端单元测试和协议向量获得快速反馈。
- 纯文档、Proxy 或与固件无关的修改不重复编译固件。
- defconfig 未变时不重复 distclean 和拉取 HAL。
- 仅在需要验证硬件、内存、时序、网络或持久化行为时烧录。
- 烧录后一次执行预定义回归用例并保留结果，避免反复手工尝试。
- 因设备、网络或权限不可用而未执行的测试明确标记“未测”，不得写成“通过”。
